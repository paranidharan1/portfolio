My part in it

  • Training pipeline, end to end. The code path from tokenised shards to checkpoints: parallelism layout, input pipeline, checkpointing and restart, on JAX and MaxText.
  • Compute scheduling. Allocating a pool of 2,000+ TPU v6e chips across workstreams (pretraining, RL, evals, inference) so each run gets what it needs and the hardware stays busy.
  • Across the stack. Because the pipeline touches everything, I work with the data, tokenizer, RL, evaluation and edge-inference efforts, and keep them compatible with each other.

02 · How I work

Systems engineering for large-scale training

⌁

Distributed training

Data, tensor and pipeline parallelism, ZeRO/FSDP, expert parallelism for MoE. Choosing layouts against the memory and interconnect budget, not by habit.

◧

TPU & XLA

JAX and MaxText on TPU v6e, orchestrated on GKE with XPK. Compile behaviour, sharding annotations and recipes that survive scale.

≋

Data & tokenizers

Large-scale curation and dedup pipelines (datatrove, NeMo Curator) feeding a custom multilingual tokenizer built for Indian languages.

↺

Reliability

Checkpoint lineage hashed from step 0, restart paths, and monitoring so that a multi-week run is reproducible and auditable.

◈

Post-training

SFT and RL on TPUs, including reward design that rewards answering in the right language and detects score gaming.

▭

Edge inference

4-bit quantisation and llama.cpp deployment to laptops, Jetson modules and Raspberry Pi class boards.

Stack JAX · MaxText · XLA · PyTorch · Megatron-Bridge · NeMo · XPK · GKE · TPU v6e · H100 · TensorRT · llama.cpp · LoRA/QLoRA
